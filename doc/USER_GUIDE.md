# 운영자 빠른 안내 (1쪽)

> 개발 지식이 없어도 이 페이지만 읽으면 바로 쓸 수 있습니다. 상세 실행 방법은 아래 본문을 참고하세요.

**이 도구는** 서버 운영팀의 AI 당직자입니다. 문제를 말하면 모니터링 수치·최근 로그·대응 매뉴얼을 직접 조회해
"지금 상태 → 원인 추정 → 지금 할 일 → 담당팀 요청 → 근거" 순서로 보고합니다.

**어떻게 물어보나** — 시스템 이름을 알면 적고, 모르면 업무 용어로 말해도 됩니다.

| 확인할 수 있는 시스템 | 이렇게 말해도 알아듣습니다 | 질문 예시 |
|---|---|---|
| payments-service | 결제 | "결제가 안 되는 것 같아요" |
| auth-service | 로그인, 인증 | "로그인이 느려요" |
| cache-service | 캐시 | "캐시 메모리가 계속 올라가요" |
| gateway-service | API 게이트웨이 | "API 요청이 타임아웃 나요" |
| log-service | 로그 수집 | "디스크 부족 알람이 왔어요" (시스템명 없이도 전체를 훑어 찾아줍니다) |
| web-01 | 웹 서버, 홈페이지 | "홈페이지가 느려요" |

**얼마나 걸리나** — 잡담은 몇 초, 장애 질문은 **1~2분**입니다. 화면의 진행 단계(✓)와 경과 시간을 보면 됩니다.
한 번에 하나씩 물어보세요.

**승인 카드가 뜨면** — 답변 초안에 "재시작, 롤백, 스케일 아웃, 삭제" 같은 되돌리기 어려운 조치가 들어 있다는 뜻입니다.
에이전트가 서버를 직접 조작하지는 않습니다. 답변에 그 조치를 넣을지만 정하는 것입니다.
- **답변에 포함(승인)** → 조치가 든 답변을 확정합니다.
- **빼고 다시 쓰기(거절)** → 거절 사유를 적을 수 있고, 조사·확인 중심으로 다시 씁니다. 거절한 조치는 답변에 "실행 금지"로 표시됩니다.

**답변 읽는 법** — 맨 위 📌 줄은 어느 시스템이 어떤 상태인지(코드가 수치로 작성), 📖 줄은 적용한 매뉴얼입니다.
그 아래 1) 상태 2) 원인 추정 3) 지금 할 일(운영자) 4) 담당팀에 요청 5) 근거 입니다.
"⚠️ 점검 기준 일부 미달 — 참고용"이 붙으면 답변 점검을 완전히 통과하지 못한 것이니 수치를 한 번 더 확인하세요.

**리포트** — 장애 질문마다 "📄 인시던트 리포트 #n 저장됨 — 열기"가 뜹니다. 헤더의 "📄 지난 리포트"에서 예전 것을 볼 수 있습니다.

**오류가 나면** — "⚠️ 서버와 연결이 끊겼습니다"가 뜨면 서버가 켜져 있는지 확인하고 같은 질문을 다시 보내면 됩니다.
