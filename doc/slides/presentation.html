개선 · 추가무엇을 바꿨나 — 모델이 틀리는 지점마다 코드가 한 번 더 확인

수정 (기본 기능 개선)

  • 모듈화 — 338줄 한 파일을 노드별 파일 + 공용 상태·프롬프트 모듈로 분리
  • RAG — 매뉴얼 6개를 벡터 인덱스로, 질문의 뜻으로 검색 + 증상 어휘 재정렬
  • 라우팅 — 장애 표현·시스템명·업무 용어("결제"→payments-service) 인식, 양방향 교정
  • 검증 강화 — 시스템명 언급·수치 인용·없는 시스템 금지를 코드로 검사, 반려 사유로 재작성

추가 (새 기능)

  • Multi-Agent — 메트릭·로그·매뉴얼 서브에이전트 3개가 동시에 조사 (MCP Tool 추가)
  • Human-in-the-loop — 재시작·롤백 등 위험 조치는 사람이 승인, 거절·승인 기억
  • 요약 메모리 — 긴 대화는 요약해 기억, 인시던트 리포트 자동 저장
  • 품질 장치 — pytest 55개, LLM-as-judge, 두 관점(개발자·사용자) 검토 27항목 반영
개선 후 그래프 — 조사 서브그래프 · RAG 재계획 · 검증/승인 루프

맞바꾼 것: 틀린 답을 빨리 주기보다 맞는 답을 늦게 주기

🔎 RAG — 한국어 임베딩

로컬 임베딩(nomic)이 "디스크 공간 부족"을 CPU 매뉴얼로 고른 적이 있어 증상 어휘 재정렬로 보완. 증상 절에 없는 표현은 여전히 임베딩에 의존.

맞바꾼 것: 단순 규칙 대신 인덱스 구축·임베딩 모델 의존

✋ HITL — 감지와 상태

위험 조치 감지가 정규식(부정문은 제외). 승인·거절 기억이 메모리에만 있어 서버 재시작 시 사라짐.

맞바꾼 것: 안전성 ↑ vs 승인 대기 1회 추가

📏 측정의 한계

fake 수치는 검증기와 같은 코드(동어반복), LLM 채점은 답을 쓴 모델이 채점. 그래서 Ollama 회귀 수치와 규칙 검사를 주 증거로.

🗂 데이터는 샘플

모니터링·로그는 JSON 샘플. MCP Tool 안의 조회 코드만 실제 API로 바꾸면 그래프·RAG·검증은 그대로 동작.

🔁 재작성 루프

검증 반려는 최대 3회, 승인 거절은 거절 조치가 재등장하면 즉시 종료 — 무한 루프는 막았지만 3회 뒤엔 "참고용"으로 통과.

이후 반영하고 싶은 개선

  • 위험 조치 감지를 LLM 판단 + 조치 화이트리스트로, 승인 상태를 SQLite 체크포인터로 영속화
  • 조치 실행 Tool(restart / scale-out)을 승인 뒤 실제 실행까지 연결 — 지금은 제안까지만
  • 실제 모니터링(Prometheus 등) 연동, 채점 모델을 작성 모델과 분리

느낀 점

  • 작은 모델은 "난 홍길동이야"를 장애로 보내고 두 서버 중 하나만 계획한다 — 모델을 믿지 말고 코드로 확인
  • Before를 먼저 재고 고치니 숫자로 설득할 수 있었고, 늘어난 지연도 숨기지 않고 설명할 수 있었다
  • 실제 화면에서 써 봐야 나오는 문제가 있었다 — 답변 두 개, 이름 잊음, 시스템명 없는 문의
